## Базовий випадок і рекурсивний крок

- `is_palindrome(s)`: база — `len(s) <= 1` → `True`; крок — `s[0] == s[-1] and is_palindrome(s[1:-1])`.
- `longest_len(s, l, r)`: база — `l > r` → 0 або весь фрагмент паліндром → його довжина; крок —
  `max(longest_len(s, l+1, r), longest_len(s, l, r-1))`. Без кешу це експонента, з `lru_cache` — O(n²) станів.
- `fib(n)`: база `n < 2`; крок `fib(n-1) + fib(n-2)`.

## Ліміт рекурсії CPython і відсутність TCO

`sys.getrecursionlimit()` за замовчуванням 1000 кадрів; глибша рекурсія дає `RecursionError`.
CPython свідомо не робить tail-call optimization: навіть «хвостовий» виклик
`return f(n - 1, acc)` створює новий кадр стеку. Тому `is_palindrome` на рядку з
кількох тисяч символів впаде, а `is_palindrome_iter` з двома індексами — ні; так само
`bfs_level_order` і `dfs_preorder_iter` безпечні для дерев будь-якої глибини, а
`preorder` — лише до ~1000 рівнів. Підняття ліміту через `sys.setrecursionlimit`
ризиковане (можливий крах інтерпретатора), тому для глибоких даних правильна відповідь —
ітерація з власним стеком/чергою.
